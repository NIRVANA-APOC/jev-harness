## 2. 主检验、最小有意义效应与非劣界限

### 2.1 主检验 = H5（密度扫描的检查密度对照）

H5 的判据在**跑前写死在代码里**（`crates/jh-app/src/m4.rs` 的 `hypothesis_section`，
先导批次已引用同一份；本批不改）：

1. **质量非劣**：相同规模下，依赖触发臂（`triggered`）的验收通过率不低于任何一个定频臂。
2. **成本更省**：相同规模下，依赖触发臂的判断请求数不高于、且至少有一项严格低于定频臂
   （判断请求数或重算输入量）。

冻结时补上**量化口径**（判据 1 的「不低于」是点估计规则，本批同时报区间）：

- **非劣界限 δ_NI = 0.10（绝对，验收率，同臂同规模的配对差）**。
  依据：① 它小于主对照的最小有意义效应 Δ=0.15（见 2.2），即「非劣」的门槛比「有意义更好」更严；
  ② 密度扫描的规模 6 上，一个任务格 = 1/12 ≈ 0.083，δ_NI=0.10 相当于「允许的退步不超过约一个任务格」，
  而每格只有 1 次重复，一个任务格的波动本来就分不出来；③ δ_NI 取 0（判据 1 的字面口径）会把
  「噪声里的一个任务格」读成失败，不是本研究要问的问题。
- **两套口径不一致时以判据 1 的点估计为准**（它是预注册规则），区间只用来定档位（见 2.3 的判定表）。

### 2.2 主对照的最小有意义效应 Δ = 0.15

- **对象**：族 A 的验收通过率，**结构维配对差**（同一判断通道下 `maintained-*` − `loop-*`），
  按同一任务、同一重复编号配对。判断通道维的同族差值同批报告，但归入探索性（2.4）。
- **Δ = 0.15（绝对）的依据**：定稿设计族 A 每臂 6 任务 × 3 重复 = **18 个任务格**，
  一个任务格的稳定翻转（该任务三次重复全部由失败变成功）= 3/18 ≈ **0.167**；
  Δ=0.15 略小于「一个任务稳定翻盘」的量级，是**本设计粒度上可操作的最小变化**——
  比它更小的差值在 6 个任务的族 A 上无法对应到任何可复述的机制改善。
- **把握度依据（先导方差素材，`m4-pilot.md` §5.7）**：σ̂ = 0.118（8 个主对照格里唯一的非零格，
  来自 `maintained-jev` 族 A 的 1 个任务格；其余 7 格为 0），保守档取 2σ̂ = 0.236。
  按先导同一公式 n = (z_{0.025}+z_{0.8})²·σ²/Δ² = 7.849·σ²/Δ²（双侧 α=0.05、power=0.8）：

  | Δ | σ̂=0.118 | 2σ̂=0.236 |
  | --- | --- | --- |
  | 0.15 | 约 5 格 | 约 20 格 |
  | 0.20 | 约 3 格 | 约 11 格 |

  → **18 格/臂**在乐观档（σ̂）对 Δ=0.15 有富余（需 5 格），在保守档（2σ̂）需 20 格、**略不足**；
  保守档下 Δ≥0.20 满足（需 11 格）。**这条不对称必须带进结论**：定稿若观测到 0.15–0.20 之间的差值，
  保守档的区间可能跨零，档位只能到「条件性支持」。σ̂ 本身只有自由度 1 的支撑（先导 7 格为 0
  很可能是同批提示词把重跑噪声压掉了），报告须同时给两档读法。

### 2.3 档位判定表（结论档位只在研究目标 §10.4 的四档内）

| 判据 1（质量非劣，点估计） | 判据 2（成本更省） | 配对差 95% 区间下界 | 结论档位 |
| --- | --- | --- | --- |
| 满足 | 满足 | ≥ −0.10 | **获得支持**（本环境） |
| 满足 | 满足 | < −0.10 | **条件性支持**（点数不劣，但区间没排除超过一个任务格的退步） |
| 满足 | 不满足 | — | **条件性支持**（只有质量一条成立，写明适用条件） |
| 不满足 | 满足 | ≥ −0.10 | **条件性支持**（成本优势成立；质量点数不利但在非劣界限内） |
| 不满足 | 满足或不满足 | < −0.10 | **不支持或被否定**（在够分辨力的设计下未达最低收益且质量恶化） |
| 可比对 < 2 组，或权重格缺失（契约族失败、块未跑） | — | — | **证据不足**（写明缺哪一格） |

「可比对」= 同一规模上「一个依赖触发臂 × 一个定频臂 × 同一臂标签」的一组读数。
δ_NI=0.10 的比较对象是**同一臂同规模**的 `triggered` 与定频格（密度扫描里两格都只跑 1 次，
区间按 Wilson 计，见 §5）。

### 2.4 主对照的定位（避免多重比较）

- **H5 是本批唯一的确认性检验**（路线图 §5 M4 的退出证据就是「回答 H5」）。
- 主对照的**结构维**（H1/H2 的累积读数）、**判断通道维**（Jev vs LLM）、族 C 各臂、复用消融，
  都是**探索性**读数：报效应量、区间与逐格读数，**不据此声称「获得支持」**；
  它们的作用是适用范围、机制归因（§10.4 末段：只有 Jev 更快 → 限定为经济收益；
  架构在多个判断器上都有收益 → 归因于架构）与失败案例。
- 归因所需的最小证据冻结为：同一配对差在**两个判断通道上同向**且都超过 1 个任务格（≈0.167），
  才在报告里写「架构维的改善不依赖具体判断通道」这类措辞；否则只写逐通道读数。

### 3.2 停止条件（跑前写死）

1. **预算到达即停**：任一项上限触顶 → 未跑的块不补跑，报告里标「未跑」，
   受影响的主检验按 §2.3 末行处理（证据不足）。
2. **失败率**：某一用途的失败调用占比 > 20% → 停止后续块，报告标「运维失败」而不是结论
   （先导的失败率 5/1141 = 0.4% 是本条的量级参照）。
3. **端点持续失败**：同一端点连续 5 次调用失败（限流 / 5xx）→ 停止该块，已完成的读数保留并如实报账。
4. **契约生成失败不重试**：某族的观察通道契约生成失败（先例：`lost_update` 被
   `DEFAULT_MAX_OUTPUT_TOKENS = 16384` 截断）→ 该族按失败态登记，该族读数不进分母、不折成「成立」，
   **不重跑、不调参**。
5. **不得因读数不利而提前停止或加跑**（研究目标 §10.3 末段）：本批不做中期分析，也不因先导或
   定稿读数方向改变样本量或阈值。

## 4. 随机种子方案与重复设计

- **本系统没有随机数发生器**（任务集、环境扰动、调度枚举都是入库/写死的确定性数据；
  族 C 的环境是确定性解释器）。
- **判断侧没有种子接口**：两条判断通道的请求路径不设 `temperature` / `seed`（代码核对：
  `crates/jh-app/src/judge/llm.rs`、`crates/jh-app/src/judge/jev.rs` 均无这两个参数），
  客户端也不支持 provider 侧 seed——**不发明项目里不存在的参数**。因此不可控的抽样只来自
  provider 侧，无法被固定。
- **冻结的是可控的那部分**：任务顺序（族 A 6 条按入库顺序、族 B 6 条未见变体按入库顺序）、
  重复编号 `1..=3`（同任务、同顺序、配对）、族 C 的调度前 3 条 × 4 路实现的固定枚举、
  密度扫描的节奏与规模枚举、执行分块与块序（§6.2）。
- **重复的用途**：估计 provider 侧抽样波动（`variance.acceptance_rate_sd` 等），
  不是「复现同一响应」的机制。先导 8 格里 7 格 σ=0，说明本环境的重跑噪声很小；
  定稿用 R=3 补上先导只有自由度 1 的方差估计。

## 5. 分析方法

| 项 | 冻结做法 |
| --- | --- |
| 配对 | 同一任务、同一顺序、同一环境快照下逐格比较；重复读数先按格聚合（比值取格内比例），再按族汇总 |
| 比例区间 | **Wilson 95% 区间**（分母 = 任务格数）；样本很小时以区间为准，不用「显著/不显著」二分 |
| 配对二元参考 | 逐任务格的不一致对计数（McNemar 精确检验）**只作参考**，n 小时区间优先 |
| 成本 | 调用数、token、输入字节按段与格的总量和每格中位数直接比较，不做显著性宣称（成本是计数不是抽样指标） |
| 概率指标 | `brier_mean` / `log_loss_mean` 按问题族报告（族 A 有隐藏真值标签；族 B 无质量标签） |
| 族 C | 检出率 / 误放行率 / 弃权率，分母 = 隐藏检查认定的机会数；契约失败族按失败态单列，不进分母 |
| 密度扫描 | 逐「规模 × 臂」列 `triggered` 与每个定频格的验收率、`asks`、`input_bytes`；H5 两条判据按 §2.1 判 |
| 多重性 | 只有 H5 是确认性；其余（主对照两维、族 C、复用消融、原生基线）标**探索性**，不参与档位判定 |
| 先导 vs 定稿 | 逐指标列两批读数；差异不追改先导文档，只在报告 §9 登记，并注明是规模变化、渠道波动还是口径变化 |

每块一次进程、各自收尾、各自落报告，

## 8. E4 诊断项（§6.9）是否安排：**未安排**（理由，核过是否仍成立）

**结论：本批仍不安排 E4，理由在先导理由之上补了可核查的代码事实。**

1. 路线图**决定 2**（1.0 不含门控场景）使 E4 的原始口径（门控漂移）在 1.0 失去对象——这条没变。
2. E4 改后的口径是「不受信内容进入判定 state 时，判定与概率的漂移」，它需要一对**同一事实、
   附加 / 不附加当前计划**的提示词。本批 runner 没有任何构造该变量的入口：`M4Options` 的维度只有
   臂（结构 × 判断通道）、证据口径、检查节奏、规模、重复次数、原生/复用开关、契约来源；
   族 A / 族 B 的任务集是入库 JSON，不含「注入计划」这类字段。**要安排就得新增一个与主对照无关的
   自变项**，那会把本批冻结的主检验（H5）与它混在一起。
3. 本批的额度已按 R=3 与族 C 前 3 条调度排满（§3.1）；按先导的每格成本，一个 2×2 提示词对诊断
   （2 个判断通道 × ≥10 样本）在千次调用量级上会挤掉主检验的余地。
4. **留作 1.x 的可行做法**（写进报告的限制清单，不静默消失）：独立的离线诊断——同一 state 两版提示词

   它是诊断项，不进主线结论。
